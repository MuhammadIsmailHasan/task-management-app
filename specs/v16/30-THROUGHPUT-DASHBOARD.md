# Throughput and Dashboard, V16 (draft)

### Requirement 43: Throughput Analytics and Dashboard

**User Story:** As a Supervisor or Manager, I want to see how many Cards my team finishes each week, so that I can judge delivery over time and not only today's counts.

Requirement 10 returns counts for now (`total`, `done`, `in_progress`, `overdue`) and `done_delta`, which counts Cards in Done whose `updated_at` is within 7 days. Any later edit of a finished Card moves `updated_at`, so that number can count a Card twice or in the wrong week, and no per-week series can be built from it. V16 stores when a Card was completed (Decision AW). The prototype's Dashboard (page 3) also draws hour estimates, capacity points, and velocity percentages; none has data, so it is not built (exclusions 6).

#### Acceptance Criteria

**Data**

1. [THR-01] THE Backend SHALL add a nullable `cards.completed_at` timestamp with time zone, in one reversible migration that adds the column, backfills it, and drops it on downgrade. THE migration SHALL set `completed_at` to the Card's `updated_at` for every non-soft-deleted Card whose Column is named `Done`, SHALL leave it null for every other Card, SHALL delete and truncate nothing, and SHALL run on a production database with data (Decision AN does not apply, because the migration is not a reset migration).
2. [THR-02] WHEN a Card is created in a Column named `Done`, or moved into a Column named `Done` from a Column with another name, THE Backend SHALL set `completed_at` to the current time in the same transaction as the move; WHEN a Card moves out of a Column named `Done`, THE Backend SHALL set `completed_at` to null; WHEN a Card moves within `Done` (a reorder), THE Backend SHALL leave it unchanged.
3. [THR-03] THE Backend SHALL keep this invariant for every non-soft-deleted Card: `completed_at` is not null exactly when the Card's Column is named `Done`. THE Backend SHALL NOT add `completed_at` to any Card payload, shared payload, or Activity_Log metadata, and no existing payload SHALL change.
4. [THR-04] THE Backend SHALL compute `done_delta` of Requirement 10 criterion 5 as the number of non-soft-deleted Cards whose `completed_at` is within the last 7 days, instead of Cards in `Done` whose `updated_at` is within the last 7 days (Open Question 42). The field name, type, and the other Analytics_Summary fields are unchanged.

**Endpoints**

5. [THR-05] WHEN a user calls `GET /api/boards/{board_id}/analytics/throughput` with an optional `weeks` query parameter, THE Backend SHALL return HTTP 200 with the Envelope and `data` of `{ "board_id", "name", "weeks": [ { "week_start": "YYYY-MM-DD", "done": integer } ], "total": integer }`. THE `weeks` list SHALL be ordered oldest first, SHALL have exactly `weeks` entries ending with the current week, and SHALL list every week even when its `done` is 0. A week runs Monday 00:00 to the next Monday 00:00 in `APP_TIMEZONE`, and `week_start` is that Monday. `total` is the sum of `done`.
6. [THR-06] THE `done` of a week SHALL be the number of Cards of that Board whose `completed_at` falls in that week and which are not soft-deleted. Archived Cards SHALL count, because archiving does not undo that the work was finished.
7. [THR-07] THE `weeks` parameter SHALL be an integer from 1 to 26 and default to 8; IF it is not an integer or is outside that range, THEN THE Backend SHALL return HTTP 400 with the code `VALIDATION_ERROR` and an `error.details` entry for `weeks`.
8. [THR-08] WHEN a Manager calls `GET /api/analytics/throughput` with the same `weeks` parameter, THE Backend SHALL return one series per Board that is not soft-deleted, ordered by name and then id, in one pre-aggregated response of the shape of criterion 5 repeated in a list, using a number of database queries that does not depend on the number of Boards or Cards (Requirement 14 criterion 12).
9. [THR-09] THE Backend SHALL apply the role rules of Requirement 10 to both endpoints: a Supervisor may read the series of a Board it owns only; a Manager may read any Board and the cross-board list; a Member and an Admin receive HTTP 403; a request without a Token receives HTTP 401; a Board that does not exist or is soft-deleted returns HTTP 404 (Requirement 10 criteria 1 to 4 and 7).
10. [THR-10] THE Backend SHALL put the new routes in the `analytics` blueprint through `routes.py`, `service.py`, `repository.py`, and `schema.py` (Requirement 13), SHALL aggregate in one grouped query without returning Card rows, and SHALL regenerate `backend/openapi.json` and update `backend/API.md` so the committed documents match the generated ones (Requirement 17).

**Dashboard page**

11. [DASH-01] THE Frontend SHALL add the Protected_Route `/dashboard`, reachable from the Dashboard item of the Top_Nav and the Icon_Rail (SHELL-05), and SHALL add `/dashboard` to the `proxy.ts` guard. WHEN a Member or an Admin opens it, THE Frontend SHALL redirect to `/boards`. THE document title SHALL be `RevoBoard | Dashboard` (Requirement 32).
12. [DASH-02] THE Dashboard SHALL show a `text-xl` title "Dashboard" and a Board selector built with `BaseCombobox`: for a Supervisor, the Boards it owns; for a Manager, "All boards" followed by every Board. The first option is selected on load.
13. [DASH-03] THE Dashboard SHALL draw its first row as the prototype's page 3 does (`03-dashboard-desktop.png`), as three cards of radius `frame` on `--surface-200` with padding 24, in a grid of one column below 960 pixels and three from 960: (a) "Board overview": the Board name, an inner `--gradient-brand` card (radius `card`) with the eyebrow "BOARD PROGRESS", the percentage done in `text-xl` on `--on-brand`, and the subtask-free count line "<done> of <total> Cards done", and under it "Completed in the last 7 days" with the `done_delta` value and a teal count badge; (b) the throughput chart of criterion 14; (c) "Open work": the open Cards count in `text-xl` (total minus done), and the In progress and Overdue figures as two rows with a tone dot each. The figures come from Requirement 10; FOR "All boards" the Frontend SHALL add the figures of `GET /api/analytics/boards`; no figure is computed from Card rows.
14. [DASH-04] THE throughput chart card SHALL be titled "Completed per week" with a 36 pixel icon tile, and SHALL show one pill-shaped bar per week of the last 8 weeks for the selected Board, or for "All boards" the sum of the weeks of every Board; the bars are `--surface-strong` pills of equal width with a `--accent` fill rising from the base, the current week's bar is solid `--accent` with its value in a dark `--ink` tooltip pill above it, and each bar is labelled below with the week start ("12 Oct", `text-2xs` upper case) and carries its value above it in `text-meta` on hover and focus; it is drawn with token colours as inline SVG or styled elements with no chart library, with `role="img"` and an accessible name that states the total, and a visually hidden table of the same values for assistive technology. A week with 0 shows an empty bar, not a gap. THE prototype's "Weekly or Monthly" switch is excluded (DASH-08).
15. [DASH-05] FOR a Manager, THE Dashboard SHALL show, as its second row, a Boards table card from `GET /api/analytics/boards` on the table card layout of SCR-15 (header row of `text-2xs` upper case labels; rows with a 40 pixel tone tile, the Board name as a link to the Board, and the figures Total, Done as a percentage, Overdue, and Completed in the last 7 days); below 960 pixels the rows stack as cards.
16. [DASH-06] FOR a single selected Board, THE Dashboard SHALL show, as its second row, a "Recent activity" card with the five newest rows of `GET /api/boards/{id}/activity?limit=5` through the existing `ActivityLine` on the Panel row recipe, with a "View all" quiet pill that opens the Activity view of the Side_Panel for that Board. For "All boards" it SHALL show no recent activity.
17. [DASH-07] THE Dashboard SHALL show a loading state (skeleton tiles and chart), an error state with a Retry button, and, for a viewer with no Board, an empty state "No boards to show yet." with a link to Home, each drawn from the Design_System recipes.
18. [DASH-08] THE Dashboard SHALL NOT show estimates, capacity, a velocity percentage, a "Weekly or Monthly" switch, or a claim that the API does not return (exclusions 6); and the Home analytics strip of Requirement 10 criterion 8 SHALL remain.
19. [DASH-09] THE Dashboard SHALL take the first row of criterion 13 and a second row of one full-width card, SHALL start with the title block of Requirement 40 (an eyebrow, the `text-xl` title "Dashboard", and the Board selector at the right), SHALL have no horizontal scroll between 360 and 414 pixels, and SHALL show no greeting, no date range, and no "Add New Card" button (exclusions 2 and 17).
